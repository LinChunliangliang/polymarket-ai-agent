# Feature Specification: Binance Copy Trading Program

**Feature Branch**: `001-binance-copy-trading`

**Created**: 2026-06-11

**Status**: Cancelled

**Input**: User description: "我想实现一个关于binance复制跟单交易员的程序，主要是可以在跟单交易员有交易时，我们可以在1s内完成我们自己帐户的同步交易"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 配置并跟单交易员 (Priority: P1)

用户通过提供交易员标识信息，将某位 Binance 交易员加入跟单列表。系统随即开始实时监控该交易员的交易动态，当交易员产生新的开仓或平仓操作时，系统在 1 秒内自动在用户自己的账户中执行相同方向的跟单交易。

**Why this priority**: 这是整个产品的核心功能。没有实时跟单，整个系统无任何价值。

**Independent Test**: 可通过"配置交易员 → 触发该交易员产生一笔真实/模拟交易 → 观察用户账户是否在 1 秒内出现对应交易"来独立测试，并交付可演示的核心价值。

**Acceptance Scenarios**:

1. **Given** 用户已输入有效的交易员标识并完成账户授权，**When** 被跟单的交易员开一笔多单，**Then** 用户账户在 1 秒内自动按配置的仓位规则开出相同方向的多单，并记录本次跟单事件。
2. **Given** 用户账户余额充足且跟单配置有效，**When** 被跟单的交易员平掉某一持仓，**Then** 用户账户在 1 秒内同步平掉对应持仓，并记录本次跟单事件。
3. **Given** 用户账户余额不足以执行跟单，**When** 被跟单交易员产生新交易，**Then** 系统跳过本次跟单，向用户发出余额不足告警，并在日志中记录失败原因。

---

### User Story 2 - 设置仓位规模与风控规则 (Priority: P2)

用户为每位被跟单的交易员分别设置仓位规模策略（如固定 USDT 金额或账户百分比），以及最大亏损阈值。当累计亏损触达阈值时，系统自动停止对该交易员的跟单。

**Why this priority**: 无风控的全自动跟单会造成不可控损失。该功能是系统能够被安全使用的前提条件。

**Independent Test**: 可通过"设置最大亏损 = 20 USDT → 模拟跟单亏损累计超过 20 USDT → 验证系统自动停止跟单并发出通知"来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户为某交易员设置了固定金额跟单（如每笔 50 USDT），**When** 该交易员开仓，**Then** 用户账户按 50 USDT 等值下单，不受交易员原始仓位大小影响。
2. **Given** 用户为某交易员设置了单日最大亏损限额，**When** 跟单累计亏损达到该限额，**Then** 系统自动暂停对该交易员的跟单，并通知用户。
3. **Given** 用户为某交易员设置了按账户百分比跟单（如 5%），**When** 该交易员开仓，**Then** 用户账户以当前可用余额的 5% 下单。

---

### User Story 3 - 查看跟单状态与历史记录 (Priority: P3)

用户可以实时查看当前所有跟单持仓、每位交易员的跟单盈亏统计，以及历史跟单记录（含成功与失败）。

**Why this priority**: 透明的状态展示是用户信任系统、做出调整决策的基础。属于运营监控能力，优先级低于核心跟单功能。

**Independent Test**: 可通过"执行若干次跟单 → 进入状态页面 → 验证当前持仓、盈亏数据与实际账户一致"来独立测试。

**Acceptance Scenarios**:

1. **Given** 系统正在跟单若干位交易员，**When** 用户查看状态面板，**Then** 显示每位交易员的当前跟单状态（启用/暂停）、当前持仓、累计盈亏。
2. **Given** 已发生多笔跟单事件，**When** 用户查看历史记录，**Then** 可按时间倒序查看每笔跟单的交易员、方向、金额、执行结果（成功/失败）及耗时。

---

### User Story 4 - 停止或暂停跟单 (Priority: P3)

用户可以随时手动停止或暂停对某位交易员的跟单，也可以一键停止所有跟单。

**Why this priority**: 用户必须拥有随时退出的控制权，这是系统安全性的基本保障。

**Independent Test**: 可通过"停止某交易员的跟单 → 该交易员产生新交易 → 验证用户账户无新增对应仓位"来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户正在跟单某交易员，**When** 用户手动停止该交易员的跟单，**Then** 系统立即停止监控该交易员，后续该交易员的任何交易不再触发跟单操作。
2. **Given** 用户希望紧急退出所有跟单，**When** 用户触发"全部停止"操作，**Then** 系统立即停止所有交易员的跟单监控。

---

### Edge Cases

- 被跟单交易员开仓时，若该交易对在用户账户不支持交易，如何处理？
- 多位被跟单交易员同时产生交易信号时，执行顺序和并发控制如何保证？
- 网络中断后恢复时，期间错过的交易信号如何处理？（补单 vs. 跳过）
- 被跟单交易员的仓位包含较高杠杆，而用户账户未开启对应杠杆倍数时如何处理？
- 跟单下单时 Binance API 触发限频，重试策略是什么？
- 用户手动在账户中操作了被跟单的持仓（如手动平仓），后续该如何同步状态？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户通过交易员唯一标识（UID 或链接）添加一个或多个需要跟单的交易员。
- **FR-002**: 系统 MUST 在被跟单交易员产生新的开仓/平仓操作后 1 秒内检测到该事件。
- **FR-003**: 系统 MUST 在检测到交易信号后 1 秒内完成用户账户的跟单下单请求提交。
- **FR-004**: 系统 MUST 支持按固定金额或账户余额百分比两种方式配置跟单仓位大小。
- **FR-005**: 系统 MUST 支持为每位跟单交易员独立配置最大单日亏损限额，触达后自动暂停该交易员的跟单。
- **FR-006**: 系统 MUST 支持同时跟单至少 5 位交易员，各交易员的跟单相互独立。
- **FR-007**: 系统 MUST 记录每笔跟单事件（含交易员、方向、金额、执行时间、结果、耗时）。
- **FR-008**: 系统 MUST 在跟单执行失败时（余额不足、API 错误等）通知用户，并记录失败原因。
- **FR-009**: 系统 MUST 允许用户随时手动停止或暂停对指定交易员的跟单。
- **FR-010**: 系统 MUST 提供当前跟单状态概览，包括各交易员状态、当前持仓及累计盈亏。
- **FR-011**: 系统 MUST 在用户账户 API Key 失效或权限不足时停止跟单并发出告警。
- **FR-012**: 系统 MUST 仅支持 Binance USDT-M 永续合约（Perpetual Futures）市场的跟单，现货交易不在本版本范围内。

### Key Entities

- **Trader（被跟单交易员）**: 被跟单的 Binance 交易员，包含其唯一标识、显示名称、当前跟单状态。
- **Follow Config（跟单配置）**: 针对某位交易员的跟单参数，包含仓位规模策略、最大亏损限额、启用/暂停状态。
- **Trade Signal（交易信号）**: 从被跟单交易员处检测到的一次开仓或平仓操作，包含交易对、方向、时间戳。
- **Copy Trade（跟单交易）**: 系统在用户账户中根据交易信号执行的一笔订单，包含执行时间、金额、结果、耗时。
- **User Account（用户账户）**: 用户的 Binance 账户，含 API 权限、可用余额、当前持仓信息。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 从被跟单交易员的交易被确认，到用户账户跟单订单提交成功，端到端延迟不超过 1 秒（P95）。
- **SC-002**: 在网络正常、账户余额充足的条件下，跟单成功率不低于 95%。
- **SC-003**: 系统可同时稳定跟单至少 5 位交易员，各交易员互不干扰，无丢单现象。
- **SC-004**: 用户完成首次配置（添加交易员 + 设置仓位规则）的操作时间不超过 5 分钟。
- **SC-005**: 当跟单亏损触达用户设定的限额后，系统在 5 秒内自动暂停该交易员的跟单并发出通知。
- **SC-006**: 历史跟单记录完整保存，支持按时间范围和交易员筛选查询。

## Assumptions

- 用户已持有有效的 Binance 账户，并已开启 API 访问权限（含交易权限）。
- 跟单市场范围为 **Binance USDT-M 永续合约（Perpetual Futures）**，现货跟单不在本版本范围内。
- 被跟单交易员的交易数据可通过 Binance 提供的公开接口或官方跟单计划接口实时获取；若交易员非公开，则需要用户自行提供访问方式。
- 跟单仓位规模默认采用"固定 USDT 金额"模式，用户可切换为"账户百分比"模式。
- 系统以命令行程序（CLI）或后台服务形式运行，暂不包含 Web UI（可作为后续迭代）。
- 系统部署在用户本地机器或私有服务器上，不涉及多用户 SaaS 架构。
- 杠杆倍数跟随被跟单交易员设置，但受限于用户账户已开启的最大杠杆倍数。
- 错过的历史信号（如系统离线期间）不补单，仅记录为"已跳过"。
