# Feature Specification: Polymarket AI 预测市场套利 Agent

**Feature Branch**: `002-polymarket-ai-agent`

**Created**: 2026-06-11

**Status**: Draft

**Input**: 构建一个 AI Agent，每10分钟自动扫描 Polymarket 上的加密领域预测市场，调用 AI 服务估算每个市场的真实概率，找出与市场价格偏差超过8%的错误定价，用 Kelly 公式计算仓位，自动通过 Polymarket CLOB API 执行下单。核心优势是结合链上数据作为信号增强判断准确性。起始资金 $500。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Agent 自动发现并执行错误定价机会 (Priority: P1)

用户启动 Agent 后，系统每 10 分钟自动扫描 Polymarket 上所有加密类预测市场，结合链上信号对每个市场估算真实概率，当发现市场价格与估算偏差超过 8% 时，自动按 Kelly 公式计算下注金额并执行交易，全程无需人工介入。

**Why this priority**: 这是整个系统的核心价值。自动化发现和执行是区别于手动操作的关键优势。

**Independent Test**: 可通过"启动 Agent → 等待一个扫描周期 → 验证日志中出现市场扫描记录、概率估算结果、以及至少一笔下单记录或'无机会'标记"来独立验证核心循环是否正常运行。

**Acceptance Scenarios**:

1. **Given** Agent 已启动且账户余额充足，**When** 扫描周期到达，**Then** Agent 在 10 分钟内完成全部加密类市场扫描，并对每个市场输出估算概率和偏差值。
2. **Given** 某市场的估算概率与当前价格偏差 > 8%，**When** Agent 完成该市场分析，**Then** Agent 自动计算 Kelly 仓位并提交下单，下注金额不超过当前余额的 6%。
3. **Given** 所有市场偏差均 < 8%，**When** 扫描完成，**Then** Agent 记录"本轮无机会"并等待下一个周期，不执行任何交易。
4. **Given** 账户余额低于最低下注门槛，**When** Agent 检测到机会，**Then** Agent 停止执行并发出余额不足告警。

---

### User Story 2 - 链上信号增强判断准确性 (Priority: P2)

Agent 在估算某个加密市场的真实概率时，会主动抓取相关链上数据（代币解锁计划、TVL 变化趋势、项目 GitHub 活跃度、大户钱包动向）作为上下文，使 AI 的概率估算比仅依赖市场描述文字更加准确。

**Why this priority**: 这是系统相对于竞争者的核心差异化优势。没有链上数据，AI 的判断与普通用户无异。

**Independent Test**: 可通过"选取一个有链上数据支撑的市场 → 分别运行有/无链上信号两个版本 → 对比估算概率差异"来验证链上信号是否真实影响了判断。

**Acceptance Scenarios**:

1. **Given** 某市场涉及一个有代币解锁事件的项目，**When** Agent 分析该市场，**Then** Agent 的上下文中包含该项目的解锁时间和解锁量数据。
2. **Given** 某项目 TVL 过去 7 天下降超过 20%，**When** Agent 分析该项目相关市场，**Then** 链上趋势数据被纳入概率估算，并在分析日志中可见。

---

### User Story 3 - 运营监控与成本管理 (Priority: P3)

用户可以随时查看 Agent 的运行状态：当前持仓、累计盈亏、本月 AI 调用费用、以及每笔历史交易记录。系统自动追踪运营成本（AI 推理费用），并在盈利中扣除，确保 Agent 自给自足。

**Why this priority**: 系统的可持续运行依赖于对成本和盈亏的清晰追踪。这也是判断策略是否真实盈利的基础。

**Independent Test**: 可通过"执行若干笔交易 → 查看状态报告 → 验证盈亏数字与实际 Polymarket 账户余额一致、AI 费用被正确记录"来独立验证。

**Acceptance Scenarios**:

1. **Given** Agent 已运行一段时间，**When** 用户查看状态报告，**Then** 显示：当前余额、起始资金、净盈亏、本周期 AI 费用支出、以及历史下注列表（含每笔的市场、方向、金额、结果）。
2. **Given** 某笔 AI 推理产生了费用，**When** 费用产生，**Then** 费用被自动记录并从可用余额中扣除，不影响已开仓的头寸。

---

### User Story 4 - 风控保护与紧急停止 (Priority: P2)

系统有多重风控保护：单笔下注上限、每日最大亏损上限、以及手动紧急停止指令。当触发任何风控条件时，Agent 自动暂停并通知用户。

**Why this priority**: 全自动系统在无人值守情况下运行，风控是防止资金快速归零的最后防线。

**Independent Test**: 可通过"设置每日最大亏损为 $50 → 模拟连续亏损超过 $50 → 验证 Agent 自动停止且不再执行新交易"来独立测试。

**Acceptance Scenarios**:

1. **Given** 当日累计亏损达到设定上限，**When** Agent 检测到这一状态，**Then** Agent 立即暂停所有新交易，记录停止原因，并等待人工重新启动。
2. **Given** Agent 正在运行，**When** 用户发出紧急停止指令，**Then** Agent 在当前扫描周期结束后停止，不开新仓（不强制平仓已有头寸）。
3. **Given** Kelly 公式计算出的仓位超过余额的 6%，**When** Agent 准备下单，**Then** 系统自动将下注金额截断至 6% 上限。

---

### Edge Cases

- 某市场的流动性极低（深度不足），下单会造成明显滑点，如何处理？
- 同一轮扫描中发现多个机会，同时下单导致余额不足怎么办？
- Polymarket 市场在扫描期间突然关闭或结算，未成交的订单如何处理？
- AI 估算结果出现极端值（如 0% 或 100%），如何防止异常下单？
- 链上数据抓取失败（网络问题），是否降级为无链上信号运行？
- 连续多个周期无机会时，如何判断系统是否正常而非卡死？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 每 10 分钟自动触发一次完整的市场扫描和分析周期。
- **FR-002**: 系统 MUST 在每个周期内扫描 Polymarket 上全部处于活跃状态的加密类预测市场。
- **FR-003**: 系统 MUST 对每个市场调用 AI 服务（默认使用 DeepSeek，可配置替换）估算其真实概率，估算结果须考虑市场描述和可获取的链上信号。
- **FR-004**: 系统 MUST 将 AI 估算概率与当前市场价格进行对比，仅对偏差超过 8% 的市场生成下注信号。
- **FR-005**: 系统 MUST 使用 Kelly 公式计算每笔下注金额，且单笔下注不得超过当前余额的 6%。
- **FR-006**: 系统 MUST 自动通过 Polymarket 的交易接口提交下单，无需人工确认。
- **FR-007**: 系统 MUST 抓取并整合以下链上数据作为分析信号：代币解锁计划、协议 TVL 变化、项目代码库活跃度、大户钱包动向。
- **FR-008**: 系统 MUST 记录每笔交易的完整信息：市场名称、下注方向、金额、AI 估算概率、市场价格、偏差值、时间戳、最终结果。
- **FR-009**: 系统 MUST 追踪并记录每次 AI 推理产生的费用，并将其计入运营成本。
- **FR-010**: 系统 MUST 在当日累计亏损超过用户设定阈值时自动暂停交易并发出告警。
- **FR-011**: 系统 MUST 支持用户随时发出紧急停止指令，Agent 在当前周期结束后停止。
- **FR-012**: 系统 MUST 在账户余额低于可执行最小下注金额时自动停止并告警。
- **FR-013**: 系统 MUST 提供运行状态报告，包含余额、净盈亏、AI 费用支出和历史交易列表。
- **FR-014**: 系统 MUST 对流动性不足（市场深度低于下注金额的 3 倍）的市场跳过下单。
- **FR-015**: 系统 MUST 在链上数据抓取失败时降级运行（仅使用市场文字描述），并在日志中标注数据缺失。

### Key Entities

- **Market（预测市场）**: Polymarket 上的一个预测事件，包含市场 ID、描述、当前 YES/NO 价格、流动性深度、截止时间、所属类别。
- **Signal（分析信号）**: AI 对某个市场的估算结果，包含估算概率、置信度、使用的链上数据摘要、与市场价格的偏差值。
- **Bet（下注记录）**: 系统执行的一笔交易，包含市场 ID、方向（YES/NO）、金额、执行时间、成交价、结算结果、盈亏。
- **OnchainData（链上数据）**: 从外部数据源抓取的链上信号，包含数据类型、相关项目、数值、时间戳、来源。
- **Portfolio（资金状态）**: Agent 的整体资金账户，包含起始资金、当前余额、已用于下注的金额、AI 费用累计、净盈亏。
- **RiskConfig（风控配置）**: 用户设定的风控参数，包含单笔上限比例、每日最大亏损额、最小下注金额门槛。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 每个扫描周期（10 分钟）内完成所有活跃加密市场的扫描和分析，无超时失败。
- **SC-002**: 在连续 30 天运行中，AI 估算概率的准确性高于随机基准（校准误差低于市场隐含概率的平均误差）。
- **SC-003**: 扣除所有运营成本（AI 费用、交易手续费）后，30 天内净盈亏为正。
- **SC-004**: 单日最大回撤不超过起始资金的 15%（风控机制有效运行）。
- **SC-005**: 系统可在无人值守的情况下连续运行 7 天，无崩溃或卡死（每日日志完整）。
- **SC-006**: 每笔实际下注金额与 Kelly 公式计算结果的误差在 ±1% 以内。

## Assumptions

- 用户已持有有效的 Polymarket 账户，账户中有 USDC 余额，且已在 Polygon 网络上完成设置。
- 起始资金为 $500 USDC，运营成本（AI 推理费用）从盈利中支付，不单独充值。
- 系统仅交易 Polymarket 上类别为"加密"的预测市场，不涉及天气、体育、政治等其他类别（可作为后续扩展）。
- 链上数据来源包括公开免费 API（DefiLlama TVL、GitHub API、代币解锁公开数据库），不依赖付费数据订阅。
- AI 概率估算默认使用 DeepSeek API，费用由系统从交易利润中自动扣除；AI 服务商设计为可配置，后续可替换为其他模型。
- 系统以后台服务形式运行在低成本 VPS（$4-6/月）上，不需要图形界面，通过日志文件和状态报告获取信息。
- 当 Kelly 公式建议下注比例为负值（即 AI 认为市场定价合理或对自己不利）时，系统不执行交易。
- 偏差阈值默认为 8%，风控单笔上限默认为余额的 6%，每日最大亏损默认为 $75（起始资金的 15%）。
- 已有持仓的市场在结算前不重复下注。
